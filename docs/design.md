# WXEditorX 설계 v1

위크로스 시뮬레이터(WXCore)용 카드 DB 에디터다. 친구의 YellowEditorX(CyanPro 오리카용, C# + WPF, .NET 8)를 포크해서 만든다.
뼈대와 화면은 그대로 쓰고, 카드 모델과 DB 스키마를 위크로스용으로 갈아끼운다.

## 결정 요약

| 항목 | 결정 |
| --- | --- |
| 출발점 | YellowEditorX 1.1.10 포크 (원작자 동의 받음) |
| 기술 | C# + WPF, .NET 8. 그대로 유지 |
| 편집 대상 | 팩 `.db` (WXCore 스키마: `cards` / `prints` / `texts` / `card_meta`) |
| 텍스트 언어 | 오리카는 한국어(`ko`)만 편집. 일본어(`ja`)는 공식 카드를 볼 때만 읽기 전용으로 보여준다 |
| 제작 정보 | `card_meta` 테이블에 저장. 카드 텍스트에 섞지 않는다 (YellowEditorX의 `[ ]` 줄 방식은 쓰지 않는다) |
| 인쇄본 | 카드(cid) 하나에 인쇄본(일러) 여러 개. 목록으로 편집 |
| 동명 취급 | `cards.alias`: 이름은 같고 색·레벨이 달라 cid가 갈린 카드를 대표 cid로 잇는다 |
| 이미지 | 팩 폴더 `pics/<cid>.png`(idx 1), `pics/<cid>_2.png` … 끌어다 놓으면 이 이름으로 복사 |
| 카드 메이커 | 연동 안 함. 카드 메이커가 뽑은 PNG를 에디터에 끌어다 놓는 것까지만 |

## YellowEditorX에서 그대로 쓰는 것

- 여러 DB를 한꺼번에 열기, 폴더 스캔(`Workspace`)
- 카드 목록·검색, 다른 DB로 복사·이동, 삭제(파일 포함)
- 되돌리기 기록(`History`, 최대 50)
- 다른 DB와 ID 중복 검사, 빈 번호 자동 배정(`NextFreeCode`)
- 스크립트 열기·새로 만들기(`EnsureScript`), 스크립트 편집기 고르기
- 이미지 가져오기(파일·클립보드·끌어다 놓기)
- 셀프 테스트, 자동 업데이트, 릴리스 스크립트

## 바꾸는 것

### 1. 먼저 끊어야 할 원본 연결 (최우선)

- `Updates.cs`: `YellowGrow/YellowEditorX` 릴리스를 보고 자동 업데이트한다. 그대로 두면 유희왕용 원본으로 덮어써진다. 시안의 포크로 바꾸거나, 포크가 생기기 전까지 끈다.
- `RemoteInfo.cs`: CyanPro 레포에서 종류·종족·속성 목록을 받아온다. 위크로스에서는 쓰지 않는다(아래 "목록 데이터").

### 2. 카드 모델과 DB

| YellowEditorX | WXEditorX |
| --- | --- |
| `datas` + `texts`(cid당 한 줄) + `card_dates` | `cards` + `texts`(cid × 언어) + `prints`(cid × idx) + `card_meta` |
| 공격력·수비력·레벨·종족·속성·카드군·링크 마커·스케일 | 종류·클래스·색·레벨·리미트·파워·비용·그로우 비용·한정 조건·팀·코인·가드·LB·사용 타이밍 |
| `alias`(일러 바꾼 버전도 alias) | `alias` = 동명 취급 전용. 일러 바꾼 버전은 `prints`의 idx로 |
| 이미지 `pics/<id>.jpg` 한 장 | `pics/<cid>.png` + `pics/<cid>_<idx>.png` |
| 제작 정보를 텍스트 끝 `[ ]` 줄로 | `card_meta`(제작자·태그·팩·제작일·수정일) |

- 스키마는 `WixossArchive\build_db.py`가 만드는 것과 똑같아야 한다. 새 팩 `.db`를 만들 때도 같은 CREATE 문을 쓴다.
- 비용 표기는 MTG식 `{W}{R}{U}{G}{B}{C}`, 혼성 `{W/B}`. 색은 비트(백1 적2 청4 녹8 흑16, 0 = 무색).
- 목록형 칼럼(종류·클래스·한정 조건·팀·사용 타이밍)은 JSON 배열 문자열이다.

### 3. 편집 화면 (오른쪽 폼)

- 이름(ko), 종류 칩, 색 칩, 레벨·리미트·파워
- 비용·그로우 비용: 에나 아이콘 버튼으로 입력하고 `{G}{G}` 문자열로 저장
- 클래스 / 루리그 타입, 한정 조건, 팀: 목록에서 고르거나 새로 입력
- 코인·가드·LB 여부, 사용 타이밍(아츠·스펠·피스)
- 능력 텍스트, LB 텍스트, 플레이버(ko)
- 동명 취급(alias)
- **인쇄본 목록:** idx · 카드 번호 · 레어도 · 일러스트레이터 · 이미지 미리보기. 추가·삭제·순서 바꾸기. idx 1이 기본 일러
- 제작 정보: 제작자, 태그, 팩, 제작일, 수정일
- 종류에 따라 칸을 숨긴다. 예: 루리그는 파워를 숨기고, 시그니는 리미트·그로우를 숨긴다.

### 4. 목록 데이터

- 클래스, 루리그 타입, 팀, 한정 조건 후보는 공식 `wixoss.db`의 값을 모아 만든다. 팩에서 새로 쓴 값은 그 팩 안에서 자동으로 후보에 추가된다.
- CyanPro GitHub에서 받아오는 기능은 뺀다.

### 5. 스크립트 템플릿

- 새 스크립트는 `script/c<cid>.lua`. 유프로식 템플릿(`local s,id=GetID()` + `s.initial_effect(c)`)을 쓰고, 첫 줄 주석에 카드 이름(ko)을 넣는다.
- 일러가 여러 장이어도 스크립트는 cid 하나에 하나다.

### 6. cid 배정

- 공식 카드는 1~999,999. 오리카 팩은 100만 단위 블록 하나를 쓴다.
- 팩을 만들 때 블록을 고르고, 새 카드는 그 블록 안의 빈 번호를 자동으로 배정한다(`NextFreeCode` 재사용).
- 열어둔 다른 DB와 cid가 겹치면 경고한다.
